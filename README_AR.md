## ما هو وايكور؟

وايكور هو **حاسوب ميداني محمول، معياري، ومتين** مصمم للاستخدام في البيئات الخارجية، وللحمل اليومي (EDC)، وحالات النجاة، والأعمال المهنية. يعتمد النظام على "هيكلية المعالجة المزدوجة" (Split-brain design): حيث يتكون من "وحدة معالجة رئيسية" (SBC) تعمل بنظام لينكس (تتولى واجهة المستخدم، الذكاء الاصطناعي، التخزين، والشبكات) مقترنة بـ "معالج مساعد" (Sidecar) من نوع ESP32-S3 منخفض الطاقة (يتولى الراديو، ونظام تحديد المواقع GPS، وإشارات الاستغاثة SOS، وإدارة الطاقة) لضمان الموثوقية واستمرار العمل حتى لو كانت الوحدة الرئيسية مشغولة أو قيد إعادة التشغيل.

### المبادئ الرئيسية

- **التركيز على الاتصالات** — مصمم للعمل عندما تفشل شبكات الهاتف والإنترنت.
- **تصميم معياري (Modular)** — يتكون من جهاز أساسي قابل للتوسيع عبر وحدات خارجية.
- **ذكاء اصطناعي محلي** — معالجة الذكاء الاصطناعي تتم على الجهاز دون الاعتماد على الخدمات السحابية.
- **الموثوقية والمرونة** — نظام الاستغاثة (SOS) يعمل بشكل مستقل حتى في حال توقف واجهة المستخدم.
- **بيئة صديقة للمطورين** — واجهات برمجية واضحة ودعم لمحاكاة العتاد (Hardware Mocking).

## البدء السريع

### المتطلبات الأساسية

- &rlm;Docker و Docker Compose
- &rlm;Python 3.11+
- &rlm;Poetry

### أوامر التطوير (موصى بها)

```bash
# تشغيل النظام بالكامل (يقوم بتنزيل النماذج عند التشغيل الأول)
./scripts/dev-start.sh

# التشغيل مع واجهة المستخدم الرسومية
./scripts/dev-start.sh --ui

# التحقق من حالة الخدمات
./scripts/dev-status.sh

# إعادة تشغيل الخدمات
./scripts/dev-restart.sh

# إعادة تشغيل خدمة محددة مع إعادة بنائها
./scripts/dev-restart.sh --service ai-service --rebuild

# إيقاف جميع الخدمات
./scripts/dev-stop.sh
```

### الإعداد اليدوي

```bash
# تشغيل البنية التحتية والخدمات
docker compose -f docker/compose/dev.yml up -d

# التحقق من عمل الخدمات
curl http://localhost:8000/health   # comms-bridge (جسر الاتصالات)
curl http://localhost:8001/health   # sensor-hub (مجمع الحساسات)
curl http://localhost:8002/health   # data-logger (سجل البيانات)
curl http://localhost:8010/health   # ai-service (خدمة الذكاء الاصطناعي)
```

### تشغيل الاختبارات

```bash
poetry install --no-interaction

# اختبارات الوحدات (Unit Tests)
poetry run pytest device/libs/ -q
poetry run pytest device/services/ -q

# فحوصات الجودة (Linting & Typing)
poetry run ruff check device/
poetry run black --check device/
poetry run mypy device/ --strict
```

## هيكلية المستودع

```
device/
├── apps/ui/              # واجهة المستخدم (Qt/QML) مع خلفية PySide6
├── libs/
│   ├── schemas/          # مخططات البيانات (Pydantic Schemas)
│   ├── hil/              # طبقة تجريد العتاد (Hardware Abstraction Layer)
│   ├── messaging/        # نظام المراسلة عبر MQTT
│   ├── database/         # قواعد بيانات SQLite (للنظام، الشبكة، والذكاء الاصطناعي)
│   └── common/           # أدوات ومكتبات مشتركة
├── services/
│   ├── core_daemon/      # إدارة حالة النظام وسياسات الطاقة
│   ├── module_manager/   # اكتشاف الوحدات وإدارة تشغيلها وإيقافها
│   ├── comms_bridge/     # تنسيق اتصالات الراديو والربط مع TAK
│   ├── ai_service/       # المعالجة المحلية للذكاء الاصطناعي
│   └── data_logger/      # حفظ وتوثيق الأحداث
└── drivers/
    ├── mock/             # محاكيات العتاد لأغراض التطوير
    └── real/             # التعريفات الفعلية للأجهزة
docs/                     # التوثيق والمستندات
progress/                 # نظام تتبع المهام
docker/                   # إعدادات Docker Compose
```

## الخدمات

| الخدمة         | المنفذ | الوصف                                             |
| -------------- | ------ | ------------------------------------------------- |
| &rlm;core-daemon    | 8000   | إدارة حالة النظام، سياسات الطاقة، وتنسيق العمليات |
| &rlm;module-manager | 8001   | اكتشاف الوحدات وإدارة تشغيلها وإيقافها            |
| &rlm;data-logger    | 8002   | تخزين واسترجاع سجلات النظام والأحداث              |
| &rlm;comms-bridge   | 8003   | تنسيق اتصالات الراديو والربط مع TAK               |
| &rlm;ai-service     | 8010   | الإجابة المرئية، تصنيف الصور، والمحادثة الذكية    |

تدعم جميع الخدمات الاتصال عبر مقابس يونكس (Unix domain sockets) (وهو الخيار المفضل) بالإضافة إلى واجهات HTTP/JSON.

## تطبيق واجهة المستخدم (UI)

توفر واجهة المستخدم المبنية على Qt/QML الميزات التالية:

- **شبكة التطبيقات** تضم مربعات للوصول السريع (الذكاء الاصطناعي، الخرائط، البوصلة، شبكة Meshtastic، الكاميرا، الملاحظات، إلخ).
- **شريط الحالة** يعرض الوقت، مستوى البطارية، وحالة الاتصال.
- **نظام السمات** يدعم الوضع الليلي (Dark Mode) المخصص للرؤية بوضوح في الخارج.
- **الإعدادات** للتحكم بالوحدات القياسية، الشاشة، وخيارات المطورين.

لتشغيل واجهة المستخدم محلياً:

```bash
cd device/apps/ui && python main.py
```

## إدارة نماذج الذكاء الاصطناعي

يقوم وايكور بتشغيل نماذج الذكاء الاصطناعي محلياً بالكامل (Offline-first). نظراً لمحدودية موارد العتاد (Raspberry Pi 5 بذاكرة 4 جيجابايت)، يمكن تفعيل **نموذج واحد فقط لكل فئة** (لغة أو رؤية) في نفس الوقت.

### النماذج الافتراضية

| النموذج       | النوع    | الحجم   | الوصف                                  |
| ------------- | -------- | ------ | -------------------------------------- |
| &rlm;Phi-3 Mini 4K | لغة (Language) | 2.3 GB | للمحادثة والأسئلة والأجوبة (GGUF, 4-bit quantized) |
| &rlm;MobileNetV3   | رؤية (Vision) | 5 MB   | لتصنيف الصور (TensorFlow Lite)          |

### تحميل نماذج مخصصة

يمكن تحميل النماذج عبر الـ API أو باستخدام السكريبت المساعد:

```bash
# باستخدام السكريبت
./scripts/upload-model.sh path/to/model.gguf --id my-model --type language

# عبر الـ API مباشرة
curl -X POST http://localhost:8010/api/models/upload \
  -F "file=@model.gguf" \
  -F "id=my-model" \
  -F "type=language"
```

### الصيغ المدعومة

- **نماذج اللغة**: GGUF (المتوافق مع llama.cpp) — مثل Phi-3, TinyLlama وغيرها.
- **نماذج الرؤية**: TensorFlow Lite (.tflite) — مثل MobileNet, EfficientNet وغيرها.

للمزيد من التفاصيل، وروابط التحميل، وحل المشاكل، راجع [دليل إدارة النماذج](docs/models/README.md).
