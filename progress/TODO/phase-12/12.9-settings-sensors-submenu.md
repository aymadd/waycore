## Description

Implement the Sensors submenu within Settings to display the live status of all hardware sensors. This screen serves as a diagnostic view showing whether each sensor is connected, operational, and providing readings. While sensors are currently mocked in development, this UI will be critical for debugging and verification once deployed to physical hardware.

### Sensors to Display

1. **GPS** - Location sensor (latitude, longitude, fix status, satellite count)
2. **Temperature** - Ambient temperature sensor (current reading, status)
3. **Barometer/Pressure** - Atmospheric pressure sensor (hPa, altitude estimation)
4. **Accelerometer** - Motion/orientation sensor (X, Y, Z values, status)
5. **Magnetometer/Compass** - Heading sensor (degrees, calibration status)
6. **Light Sensor** - Ambient light level (lux, status)

### UI Design

Each sensor should be displayed as a card showing:
- Sensor name and icon
- Status indicator (🟢 Online, 🟡 Calibrating, 🔴 Offline/Error)
- Last reading value with timestamp
- Additional details expandable on tap (accuracy, raw values, etc.)

The screen should periodically poll sensor status from the backend API (or use mock data when backend is unavailable).

### Backend Integration

- Query the core_daemon or module_manager service for sensor status
- Use SensorBridge (existing Python-QML bridge) to fetch data
- Handle connection failures gracefully with "mock data" fallback
