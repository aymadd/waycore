## Description

Create a comprehensive ecosystem for third-party developers to build, package, and distribute applications and hardware modules for Waycore devices. This includes developer documentation, SDK/tooling, app packaging format, and a module protocol specification for hardware developers.

### Goals

1. **Lower barrier to entry** — Make it easy for developers to create apps
2. **Consistent UX** — Apps follow the design system and feel native
3. **Hardware extensibility** — Clear protocol for external modules
4. **Security** — Sandboxed apps with permission system
5. **Distribution** — Simple way to share and install apps

## Part 1: Third-Party Applications

### App Development Kit

1. **Design System Package**
   - Export Theme.qml constants as reusable package
   - Provide component library (Button, Card, TextField, etc.)
   - Design guidelines and best practices documentation
   - Example templates for common app types

2. **SDK Features**
   - Access to sensor data (GPS, compass, temperature, etc.)
   - Message bus integration for inter-app communication
   - Storage APIs (local app data, shared photos, etc.)
   - Network APIs (with permission)
   - Hardware abstraction for camera, flashlight, etc.

3. **App Packaging**
   - Single-file app bundle format (`.wcapp`)
   - Manifest with metadata, permissions, dependencies
   - Icon and screenshots for app listing
   - Signed packages for verified developers

4. **App Permissions**
   - Location access
   - Camera access
   - Network access
   - Sensor data
   - Inter-app communication
   - Background execution

### App Bundle Format

```
myapp-1.0.0.wcapp
├── manifest.json         # App metadata, permissions, entry point
├── icon.png              # App icon (128x128)
├── qml/                  # QML UI files
│   └── Main.qml
├── assets/               # Images, fonts, data files
├── lib/                  # Python backend (optional)
└── README.md             # App description
```

### Manifest Example

```json
{
  "id": "com.example.myapp",
  "name": "My App",
  "version": "1.0.0",
  "author": "Developer Name",
  "description": "A useful field app",
  "entry": "qml/Main.qml",
  "icon": "icon.png",
  "permissions": [
    "location",
    "sensors.temperature",
    "storage.photos.read"
  ],
  "min_waycore_version": "1.0.0"
}
```

## Part 2: Hardware Module Development

### Module Protocol Specification

1. **Physical Interface**
   - Connector pinout documentation
   - Voltage levels and power budget
   - Communication protocols (UART, I2C, SPI)

2. **Module Identification**
   - Module ID register/response
   - Capability declaration
   - Power requirements advertisement

3. **Data Protocol**
   - Standard message framing
   - Common data types (sensor readings, status, commands)
   - Error handling

4. **Driver Development**
   - HIL interface templates
   - Mock driver examples
   - Testing framework for module drivers

### Module Developer Kit

```
module-dev-kit/
├── docs/
│   ├── hardware-interface.md    # Pinout, electrical specs
│   ├── protocol-spec.md         # Communication protocol
│   └── driver-development.md    # Software driver guide
├── examples/
│   ├── temperature-module/      # Example sensor module
│   └── display-module/          # Example I/O module
├── templates/
│   ├── module-driver.py         # Driver template
│   └── module-firmware/         # Arduino/ESP template
└── tools/
    ├── module-simulator.py      # Test without hardware
    └── protocol-analyzer.py     # Debug communication
```

### Module Manifest

```json
{
  "module_id": "TEMP_SENSOR_PRO_V1",
  "vendor": "Example Corp",
  "name": "Pro Temperature Sensor",
  "version": "1.0",
  "capabilities": ["temperature", "humidity"],
  "power_ma": 25,
  "protocol": "uart",
  "baud_rate": 115200,
  "data_format": "json"
}
```

## Part 3: Distribution

### App/Module Distribution Options

1. **Direct sharing** — Share `.wcapp` files directly
2. **Community repository** — Curated app/module listings (future)
3. **Developer portal** — Upload and manage apps (future)

### Installation Flow

1. User receives app file (download, USB, share)
2. System verifies package signature
3. User reviews permissions
4. App installed to apps directory
5. App appears in Home grid

## Validation Commands

```bash
# Package an app
python tools/waycore-pack.py myapp/ --output myapp-1.0.0.wcapp

# Verify app package
python tools/waycore-pack.py --verify myapp-1.0.0.wcapp

# Install app on device
curl -X POST -F "app=@myapp-1.0.0.wcapp" http://device/api/apps/install
```
