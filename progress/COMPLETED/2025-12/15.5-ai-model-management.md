## Description

Create a model management system that allows users to upload and manage AI models on the device. Given hardware constraints (4GB RAM, limited storage), enforce one active model per category (vision, language). Provide clear documentation and tooling.

## Constraints

### Hardware Limits (Raspberry Pi 5)
- **RAM**: 4GB total, ~2.5GB available for AI
- **Storage**: 64-128GB SD card typical
- **Power**: Battery-powered, model loading is expensive

### Model Limits
- **One active language model** at a time (e.g., Phi-3 OR TinyLlama)
- **One active vision model** at a time (e.g., MobileNetV3 OR PlantNet)
- User can have multiple models stored, but only one per type is loaded
- Switching models requires unload/load cycle

## API Design

### List Models
```
GET /api/models

Response:
{
  "models": [
    {
      "id": "phi3-mini",
      "type": "language",
      "name": "Phi-3 Mini 4K",
      "format": "gguf",
      "size_mb": 2300,
      "active": true,
      "path": "/opt/waycore/models/language/phi-3-mini.gguf"
    },
    {
      "id": "tinyllama",
      "type": "language",
      "name": "TinyLlama 1.1B",
      "format": "gguf",
      "size_mb": 800,
      "active": false,
      "path": "/opt/waycore/models/language/tinyllama.gguf"
    }
  ],
  "limits": {
    "language": {"max_active": 1, "current_active": "phi3-mini"},
    "vision": {"max_active": 1, "current_active": "mobilenetv3"}
  }
}
```

### Upload Model
```
POST /api/models/upload
Content-Type: multipart/form-data

Fields:
- file: model file (required)
- id: unique model ID (required)
- type: "language" or "vision" (required)
- name: display name (optional)
- activate: "true" to set as active (optional)

Response:
{
  "success": true,
  "model_id": "custom-llm",
  "size_mb": 1500,
  "message": "Model uploaded. Use /api/models/custom-llm/activate to enable."
}
```

### Activate Model
```
POST /api/models/{model_id}/activate

Response:
{
  "success": true,
  "message": "Model 'tinyllama' is now active for language tasks.",
  "previous_active": "phi3-mini"
}
```

## AI Model Management

Waycore supports on-device AI with swappable models. Due to hardware constraints,
only one model per category (language, vision) can be active at a time.

### Default Models

| Model | Type | Size | Description |
|-------|------|------|-------------|
| Phi-3 Mini 4K | Language | 2.3GB | Default chat/Q&A model |
| MobileNetV3 | Vision | 5MB | Default image classifier |

### Uploading Custom Models

See [Model Management Guide](docs/models/README.md) for detailed instructions.

Quick upload via script:
```bash
./scripts/upload-model.sh path/to/model.gguf --id my-model --type language
```

Or via API:
```bash
curl -X POST http://localhost:8010/api/models/upload \
  -F "file=@model.gguf" \
  -F "id=my-model" \
  -F "type=language"
```

### Supported Formats

- **Language models**: GGUF (llama.cpp compatible)
- **Vision models**: TensorFlow Lite (.tflite)
```

## Implementation Notes

### Completed 2025-12-26

1. **API Endpoints** (`device/services/ai_service/api.py`):
   - `GET /api/models` - Lists all models with active status
   - `POST /api/models/upload` - Multipart form upload with streaming
   - `POST /api/models/{model_id}/activate` - Activate and unload old
   - `DELETE /api/models/{model_id}` - Delete inactive models
   - `GET /api/models/{model_id}/info` - Model details
   - `POST /api/models/rescan` - Detect new models on disk

2. **Model Registry** (`registry.json`):
   - Tracks all installed models with metadata
   - Stores active model per category (language, vision)
   - Auto-detects models from filesystem on scan

3. **CLI Scripts**:
   - `scripts/upload-model.sh` - Upload with validation
   - `scripts/download-models.sh` - Download default models

4. **Documentation** (`docs/models/README.md`):
   - Hardware constraints and limits
   - Download instructions for default models
   - Upload via API and script
   - Model sources (HuggingFace, TensorFlow Hub)
   - Full API reference
   - Troubleshooting guide
