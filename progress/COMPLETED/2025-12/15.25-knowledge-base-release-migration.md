# Task: Migrate Knowledge Base to waycore-knowledge Releases

**Phase**: Phase 15 - AI App

## Description

Migrate from the current local document/index generation workflow to fetching pre-built knowledge base artifacts from the `waycore-knowledge` GitHub repository releases. This eliminates the need to download PDFs, parse them locally, and generate embeddings during development or deployment.

## Current State (Problems)

1. **Complex local build**: Requires downloading PDFs, parsing with PyMuPDF, generating embeddings
2. **Long build times**: RAG index build takes 7-10 minutes on RPi5
3. **External dependencies**: Downloads fail if source URLs change or are unavailable
4. **Inconsistent indexes**: Different machines may produce slightly different indexes
5. **Large repo size**: Raw PDFs and generated artifacts bloat the repository

### Current Files to Replace

```
data/raw/           # ~50MB of downloaded PDFs
data/outdoor/       # ~100MB of processed knowledge base
  ├── knowledge.db  # SQLite + FTS5 database
  └── knowledge.idx # Hnswlib vector index

scripts/download-rag-sources.sh  # Download PDFs
scripts/build-rag-index.py       # Parse and index
```

## Target State (Goals)

1. **Single download**: Fetch pre-built `knowledge.db` + `knowledge.idx` from releases
2. **Fast setup**: < 30 seconds to download and verify artifacts
3. **Consistent data**: Same knowledge base across all environments
4. **Smaller repo**: No raw PDFs or generated files in git
5. **Version tracking**: Know which knowledge base version is deployed

### External Repository

**Repository**: `dmitry-grechko/waycore-knowledge`
**Release Example**: https://github.com/dmitry-grechko/waycore-knowledge/releases/tag/v1.0.1

**Release Assets**:
- `knowledge.db` - SQLite database with FTS5 index
- `knowledge.idx` - Hnswlib vector index
- `manifest.json` - Version, entry count, categories, checksums
- `sources.txt` - List of source documents and their versions

## Implementation Plan

### Phase 1: Download Script

Create `scripts/download-knowledge.sh`:

```bash
#!/bin/bash
# Download pre-built knowledge base from waycore-knowledge releases

REPO="dmitry-grechko/waycore-knowledge"
DATA_DIR="${1:-data/outdoor}"
VERSION="${2:-latest}"

# Fetch release info
if [[ "$VERSION" == "latest" ]]; then
  RELEASE_URL="https://api.github.com/repos/$REPO/releases/latest"
else
  RELEASE_URL="https://api.github.com/repos/$REPO/releases/tags/$VERSION"
fi

# Download assets
mkdir -p "$DATA_DIR"
# ... download knowledge.db, knowledge.idx, manifest.json
# ... verify checksums
```

### Phase 2: Docker Integration

Update `docker/compose/dev.yml`:

```yaml
ai-service:
  environment:
    - RAG_DATA_DIR=/app/data/outdoor
    - KNOWLEDGE_VERSION=v1.0.1  # Or 'latest'
  volumes:
    - waycore-knowledge:/app/data/outdoor  # Named volume for downloaded data
```

Add init container or entrypoint to download knowledge base on first start.

### Phase 3: CI/CD Integration

Update `.github/workflows/build.yml`:

```yaml
- name: Download Knowledge Base
  uses: robinraju/release-downloader@v1
  with:
    repository: dmitry-grechko/waycore-knowledge
    latest: true
    fileName: "*.db"
    out-file-path: "data/outdoor"
```

### Phase 4: Deprecate Local Scripts

- Mark `scripts/download-rag-sources.sh` as deprecated
- Mark `scripts/build-rag-index.py` as development-only (for waycore-knowledge repo)

## Compatibility Requirements

### File Format Compatibility

The downloaded knowledge base must be compatible with:

- `HybridKnowledgeStore` class in `device/services/ai_service/rag/store.py`
- SQLite schema with FTS5 virtual tables
- Hnswlib index with 384-dim vectors (all-MiniLM-L6-v2)

### Version Requirements

- Knowledge base built with same SQLite version
- Hnswlib index built with compatible hnswlib version
- Embedding dimension matches (384)
